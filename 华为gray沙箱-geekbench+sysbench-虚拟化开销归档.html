华为 Gray 沙箱 · geekbench + sysbench 虚拟化开销独立归档

host 裸金属 vs guest 沙箱对比 · arm 节点 10.30.42.77 · 2026-11-17 · Geekbench 7.1.0 Preview / sysbench v1.0.20

一句话结论

CPU 虚拟化开销整体很小：微基准（sysbench）~0.1% 可忽略；真实混合负载（geekbench 单核）−5.7%，是更贴近实际的量级。

单核 5.7% 的开销中可能混入「跨 NUMA 漂移」成分（当前 guest 的 cpuset.mems 为空、4 个 NUMA 节点间自由漂移），这正是后续 NUMA 绑核绑内存优化项的靶点。

三、geekbench7（Score，越高越好，单次）

Single-Core13841305−5.7%
Multi-Core35139（160 核全跑）4080（4 vCPU）核数不同，不可直接比

geekbench 是贴近真实应用的混合负载（分支 / 加密 / SIMD / 访存），对 VM-exit、EPT 缺页、TLB 更敏感，故单核开销明显高于 sysbench。

多核口径说明：host 跑满 160 核（35139）、guest 仅 4 vCPU（4080），核数不同不可直接比。单核对比才是干净的虚拟化开销指标。若要 4 核对 4 核的多核对比，需对 host 用 taskset -c 限核重跑（本报告未做，列为可选后续）。

四、结论

  • sysbench（CPU-bound 微基准）：1t −0.08% / 4t −0.16%，基本可忽略。
  • geekbench（真实混合负载）：Single-Core −5.7%，是贴近实际的虚拟化开销量级。
  • 多核不可比：160 核 vs 4 vCPU，需限核重跑才有干净多核口径。
  • 与 NUMA 的关联：guest 4 vCPU 当前 cpuset.mems 为空、可在 4 节点间漂移（跨节点距离 35~40），单核 5.7% 中可能混入跨 NUMA 访问/迁移成分——这正是 NUMA 绑核绑内存优化项的靶点（HostOS 优化报告第一节第 1 项）。

五、方法论备注 / 坑

  • host 无外网、geekbench 须联网上传后才打印分数：用 ssh -R 127.0.0.1:443:browser.geekbench.com:443 反向隧道借道跳板机 147 让 host 出网，配合 /etc/hosts 映射（端到端 TLS，无 MITM），上传成功取得分数（result id 902594）。
  • host 侧 sysbench 依赖：LD_LIBRARY_PATH 只补 host 真缺的 lib，切勿覆盖 host 自有 libnettle/libhogweed（会触发 libgnutls.so.30: undefined symbol nettle_sm4_crypt）。
  • geekbench_aarch64（148MB）必需：缺它报 Unable to find benchmarks for the architecture 'aarch64'；且它是可执行引擎，base64 落盘后丢失执行位需 chmod +x。
  • 传输：470MB（3 文件）+ 148MB 经终端 1MB 分块 base64 → 147 → scp 至 host，md5 全部一致。
