华为 Gray 沙箱 · 宿主机(Host OS)优化项分析

生成日期：2026-11-12  ·  对象：x86 ECS 10.30.33.139（AMD EPYC 9T25）+ arm ECS 10.30.33.67（鲲鹏 920） ·  视角：沙箱 ppt_replay harness / workload.py 的宿主侧调优

一、一句话结论

两台宿主机 CPU 富余（内存空闲 1.4TiB / 1.0TiB）、THP=always 与 mitigations=off 均已到位；真正的短板是「无 NUMA 绑核绑内存 + 无隔离核（isolcpus/nohz_full）+ halt_poll_ns 收缩被关闭」。其中 NUMA 绑核绑内存最可能直接消掉此前 arm harness 逐轮 std 高达 3.5~4.3% 的「宿主漂移」。

性价比排序：① NUMA 绑核绑内存（消方差）> ② halt_poll_ns（提延迟、代价≈0）> ③ tdp_mmu=Y（EPT 缺页）> ④ isolcpus/nohz_full（去 jitter）> ⑤ AVIC（收益可能大但兼容性风险高）。cluster 调度域（CLS）已评估：arm 存在该级、x86 基本无；对 4 vCPU 单流 harness 属二阶微调，低杠杆，不纳入。

三、可优化项详细分析

1. vCPU / 内存未按 NUMA 绑核绑内存 高

当前值：cpuset.cpus = 8-511（x86）/ 8-143（arm），cpuset.mems 为空 → 内存可落任意远端节点。

含义：沙箱的 4 个 vCPU 线程与 8GB 内存在 2~4 个 NUMA 节点间自由漂移；内存没有绑定，可被分配到任意远端 NUMA 节点。

作用：4 核 guest 在 NUMA 距离 32（x86）/ 40（arm）的节点间跳来跳去，导致 ① 远端内存访问延迟 2~3×；② vCPU 迁移丢失 cache/TLB；③ 调度抖动。这正是此前 arm harness 逐轮 std 高达 3.5~4.3%「宿主漂移」的头号嫌疑。

优化方向：每个沙箱的 cpuset.cpus 固定到单节点内的一段核、cpuset.mems 绑定同一节点；或 cloud-hypervisor 启动用 --cpus 配合 numactl --membind。

预期/风险：显著压方差，mean 或小幅下降；需改 conductor 的 cpuset 分配逻辑，属于工程改造。

2. halt_poll_ns 收缩关闭（只增不减） 高

当前值：x86 200000（200us）/ arm 500000（500us）；halt_poll_ns_grow=2、grow_start=10000、shrink=0。

含义：vCPU 执行 HLT/WFI 后，VMM 先忙等 halt_poll_ns 时间再真正让出 CPU，用空转换取「短 idle 后立即唤醒」的低延迟。

作用：harness 的 32 条短命令、npm 的 node 子进程、workload 的 fork 64 子进程，都是短 idle-wakeup 密集；halt_poll 能省掉「睡眠→唤醒」的调度/中断往返。当前 shrink=0 意味着忙等窗口只增不减，无法自适应回落。

优化方向：宿主 CPU 几乎全空（空闲 1.4TiB/1.0TiB），空转代价≈0。x86 可试提到 300~500us，arm 已较激进；并打开 shrink 让其自适应。

预期/风险：「延迟换宿主空转」，此环境下性价比高；风险低，可在线验证。

3. 无 isolcpus / nohz_full（tick 抖动，x86 尤甚） 中

当前值：cmdline nohz=off（明确关掉动态 tick），无 isolcpus/nohz_full/rcu_nocbs；宿主 CONFIG_NO_HZ_FULL=y 已编译（仅被 nohz=off 关掉）。

含义：所有 512/160 个核都按 HZ 被周期 tick 打断，没有为 vCPU 预留「无 tick 隔离核」。x86 宿主 HZ=1000（1ms tick）、arm HZ=250（4ms tick），x86 tick 压力是 arm 的 4 倍。

作用：vCPU 跑 guest 时，宿主 tick、RCU 回调、中断会周期性抢占，对短命令密集、fork/exec 密集的负载带来 jitter。

优化方向：划一段专用核做 isolcpus=... + nohz_full=... + rcu_nocbs=...（去掉 nohz=off，改 cmdline 即可、不用重编内核），宿主 housekeeping 任务绑到 0-7。

预期/风险：收益中等，但要重构 conductor 的核分配逻辑，工程量大。

4. tdp_mmu = N（EPT 缺页走 legacy MMU） 中

当前值：x86 /sys/module/kvm/parameters/tdp_mmu = N。

含义：新一代 TDP MMU 被关闭，KVM 走 legacy MMU 处理 EPT 缺页与 TLB 维护。

作用：memory 阶段 256MB 分配、npm 创建 4318 文件 → 大量 EPT 缺页；legacy MMU 缺页路径慢、多 vCPU 时争用 mmu_lock 扩展性差。

优化方向：评估 tdp_mmu=Y（上游默认开，较安全）。若当年因某 bug 关掉，值得重新验证。

预期/风险：中等收益、低风险，可在线验证。

5. kvm_amd.avic = N（中断注入走 vmexit） 中

当前值：x86 kvm_amd.avic = N、force_avic = N（同时 nested=1、sev=Y）。

含义：AVIC 是 AMD 的硬件虚拟中断加速（guest APIC 由硬件直通），关闭后中断注入需 trap 进 VMM 软件模拟。

作用：fork/exec、soffice、node 均中断/IPI 密集；AVIC 关闭会放大每次 timer/IPI/设备中断的 vmexit 成本。

优化方向：评估 avic=1。

预期/风险：收益可能大，但 ⚠️ AVIC 与 nested、sev 有兼容性约束（很可能正因此被禁用），必须先验证稳定性；冲突则保持关闭，改从 halt_poll/调度侧补。

6. numa_balancing=1 与绑核冲突 低

当前值：两节点 kernel.numa_balancing = 1。

含义：宿主 NUMA 自动平衡开着，会周期性扫描并迁移「放错节点」的页。

优化方向：做了绑核落地后置 kernel.numa_balancing=0，避免自动平衡来回迁 guest 页制造 churn。

7. arm twed_enable = N（WFE 不 trap） 低

当前值：arm twed_enable = N、twedel = 0。

含义：TWED(Trap WFE Delay)控制 guest 执行 WFE 自旋时是否 trap 进 VMM 并延迟。

作用：不 trap → guest 自旋耗宿主核但零延迟；trap+delay → 省核但有延迟。

优化方向：宿主 CPU 富余，默认保持；仅当观测到 guest WFE 空转明显才考虑开 + 小 twedel。

8. guest 内存用 1GB 大页（进阶，x86） 低

当前值：THP 已 [always]（2MB）；静态大页未预留（HugePages_Total=0）；x86 支持 pdpe1gb。

含义：2MB 大页已降低 EPT 页表层级；1GB 大页可再降一级。

优化方向：给 guest 内存用 1GB hugetlbfs（需改 cloud-hypervisor 内存后端）。收益有限，优先级低。

9. C-state 深度 低

当前值：x86 acpi_idle + menu；arm cpuidle = none（已常活跃）。

含义/作用：深 C-state 增加 vCPU 突发唤醒延迟；arm 无 cpuidle 驱动已是天然低延迟。

优化方向：x86 可试 processor.max_cstate=1；有 halt_poll 后收益被部分掩盖。

10. cluster 调度（共享 L2 调度域） 低·不纳入

概念：调度域层级 SMT → MC → CLUSTER → DIE → PKG → NUMA 中的 CLUSTER（CLS）级（CONFIG_SCHED_CLUSTER），专门建模「一小组核共享同一块 L2」，用于「唤醒放置」时在「同 cluster 缓存亲和」与「跨 cluster 摊薄 L2 容量」之间取舍；源自 ARM DynamIQ/DSU 与 x86 混合架构（E-core 簇共享 L2）。

现状映射：

  • arm 鲲鹏 920：CONFIG_SCHED_CLUSTER=y 已编译，/proc/sys/kernel/sched_cluster 已暴露 → 宿主调度域存在 CLUSTER 级。
  • x86 AMD EPYC 9T25：CONFIG_SCHED_CLUSTER_PAIR=m（非标准 CLUSTER），Zen 每核 L2 私有、仅 CCX/CCD 共享 L3，不存在「多核共享 L2」的 cluster → 等价决策发生在 MC/DIE（L3）级。

不纳入原因：harness 是 4 vCPU、fork/exec 密集、唤醒/延迟敏感、单流为主，不是 L2 容量受限；4 vCPU guest 内不出现 CLUSTER 级（guest 侧无从谈起）；「亲和 vs 摊薄」属二阶微调，收益被 ① NUMA 绑核完全盖住。

调度器与相邻旋钮：宿主调度器为 EEVDF（内核 6.6.0-72，CFS 已被替换，叠加 HCE/Euler 扩展）。经典 CFS 旋钮（sched_latency_ns / sched_wakeup_granularity_ns / sched_migration_cost_ns）已不存在（6.6 起被 EEVDF 删除）。实测可用旋钮：debugfs base_slice_ns=2.8ms、migration_cost_ns=0.5ms、nr_migrate=32；sysctl sched_migration_cost、sched_protect_slice_timeout_ns、sched_prio_load_balance_enabled；arm 另有 sched_cluster（CONFIG_SCHED_CLUSTER=y）。对 4 vCPU 单流 harness 仍是二阶微调，优先级低。

11. irqbalance 全核 IRQ 亲和（IRQ 未从 vCPU 核隔离） 低

当前值：两节点 irqbalance = active，/proc/irq/default_smp_affinity = 全核。

含义：网卡/存储/timer IRQ 可在任意核投递，未被引导离开 vCPU 核。

作用：harness 短命令期间，宿主网卡（冷 npm）/存储/定时器 IRQ 随机抢占 vCPU 核 → 抖动。

优化方向：配合 isolcpus 把 IRQ 亲和从 vCPU 核挪走（/proc/irq/<n>/smp_affinity_list），或关 irqbalance 改静态绑定；低风险，可在线验证。

五、落地建议与验证思路

  1. 先做 NUMA 绑核绑内存（第 1 项）：改动集中在 conductor 的 cpuset 分配，收益目标是把 arm/x86 harness 逐轮方差压下来。
  2. 再调 halt_poll_ns + tdp_mmu（第 2、4 项）：低风险、可在线改，改完用同一套 ppt_replay harness（读 sum_ns）与 npm 热装做 A/B 对照，量化 vmexit/唤醒路径收益。
  3. AVIC（第 5 项）单独灰度：因兼容性风险，先在一台验证节点开 avic=1 跑稳定性 + 基准，再决定是否推广。
  4. isolcpus/nohz_full（第 3 项）作为中期改造：与绑核一起做，才能兑现「去 jitter」的完整收益；宿主 CONFIG_NO_HZ_FULL=y 已编译，改 cmdline 即可。
  5. cluster 调度不纳入主路径：已核实 arm CONFIG_SCHED_CLUSTER=y、x86 CONFIG_SCHED_CLUSTER_PAIR=m；调度器为 EEVDF，经典 CFS 旋钮已随 6.6 删除（可调 base_slice_ns/migration_cost_ns 等），对 4 vCPU 单流 harness 均为低优。

验证手段复用既有口径：harness 用前端 ppt_replay 的 performance.summary.commands.sum_ns（32 条命令累计耗时）；workload 用 python3 /opt/aries/workload.py 各阶段秒数。宿主侧改动需在节点上操作并注意回滚记录。
